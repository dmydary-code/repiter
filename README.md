# Репитер 🦜

Телеграм-бот для заучивания слов методом интервальных повторений.

Кидаешь боту слово — он в случайные моменты дня присылает его в смешном
предложении, где слово выделено жирным, а перевод спрятан под спойлер.
Под каждым сообщением две кнопки: **Я выучила** двигает слово дальше по
лесенке интервалов, **Ещё хочу потом** возвращает на шаг назад.

Живёт целиком в GitHub Actions. Отдельного сервера нет: состояние хранится
в `data/state.json` и коммитится обратно в репозиторий.

---

## Как это работает

Бот — долгоживущий процесс внутри job-а Actions. Он держит открытое соединение
с Telegram (long polling), поэтому **на команды и присланные слова отвечает
мгновенно**. Параллельно отсчитывает тики по полчаса и на каждом решает,
не назрела ли карточка.

Job в Actions живёт максимум 6 часов, поэтому цикл сам выходит через 5 ч 40 мин,
а расписание `*/20` держит в очереди следующий запуск — он стартует сразу,
как только освободится место. Если бот упадёт, очередь поднимет его в течение
20 минут; сообщения за это время не потеряются, Telegram хранит их сутки.

```
listen.yml  ─┬─ getUpdates (long poll)  → ответ за доли секунды
             ├─ тик раз в 30 минут      → одно напоминание за тик
             └─ push state.json         → после каждого значимого события
```

### Тики и лесенка

Время внутри бота измеряется не часами, а **тиками по 30 минут**:
`tick = unix_seconds // 1800`. Номер тика глобальный и не зависит от того,
когда запустился процесс, поэтому смена job-а в Actions ничего не сдвигает,
а повторный проход того же тика гарантированно не шлёт дубль.

Свежее слово показывается не в ближайший тик, а через один. Дальше лесенка
(таблица — `LADDER` в `bot/srs.py`, менять там одним числом):

| Шаг | Тиков | Это |
|-----|-------|-----|
| первый показ | 2 | час после добавления |
| 1 | 16 | 8 часов |
| 2 | 48 | сутки |
| 3 | 144 | 3 дня |
| 4 | 336 | неделя |
| 5 | 672 | 2 недели |
| 6 | 1440 | месяц |
| 7 | 4320 | 3 месяца → архив |

Ровно 48 тиков в сутках. За один тик уходит максимум одно напоминание, всего
не больше 8 в день. Тики идут круглосуточно, но ночью бот молчит: назревшая
карточка ждёт первого тика внутри окна 10:00–22:00 МСК. Если на сообщение так
и не нажали кнопку, бот переспросит через 48 тиков.

Пользователю бот никогда не сообщает, когда придёт следующий показ: половина
пользы приёма в том, что повторение застаёт врасплох. По той же причине в
`/list` есть прогресс, но нет расписания.

Напоминание всегда состоит из живого предложения со словом и спрятанного под
спойлер перевода. Если пример придумать не удалось, сообщение не отправляется
вовсе, а карточка остаётся назревшей и уходит следующим тиком — голое слово
с переводом ничего не закрепляет.

## Установка

### 1. Репозиторий должен быть публичным

Это обязательное условие: на приватном репо 2000 минут Actions в месяц
закончатся примерно за полтора дня непрерывной работы, на публичном минуты
безлимитны.

Settings → внизу **Danger Zone** → **Change repository visibility** → Public.

Публичными станут код и `data/state.json`, то есть список изучаемых слов.
Токены не станут: секреты шифруются, не показываются никому и не передаются
в воркфлоу, запущенные из форка по pull request.

### 2. Бот в Telegram

[@BotFather](https://t.me/BotFather) → `/newbot` → имя (`Репитер`) и юзернейм
(например `repiter_words_bot`). Выдаст токен вида `123456789:AAF...`.

### 3. Ключ для генерации примеров

По умолчанию бот ходит в **Gemini Flash-Lite** — у него бесплатный тариф
с 1500 запросами в сутки, чего хватает с большим запасом.

Ключ заводится в [Google AI Studio](https://aistudio.google.com/apikey)
кнопкой «Create API key», карта не нужна. Сейчас выдаются ключи вида `AQ.…` —
это нормально, старый формат `AIza…` Google выводит из обращения.

Важная деталь: ключи `AQ.` работают только на **нативном** эндпоинте Gemini
с заголовком `x-goog-api-key`. На OpenAI-совместимом пути через
`Authorization: Bearer` они отвечают «Please pass a valid API key», хотя сами
исправны. Бот по умолчанию ходит нативным путём, так что делать ничего не надо
— но если решишь переопределить `LLM_API_URL`, про это стоит помнить.

Учти: на бесплатном тарифе Google явно оговаривает, что содержимое запросов
используется для улучшения их продуктов. Слова, которые ты учишь, туда уедут.

### 4. Секреты

Settings → Secrets and variables → Actions → New repository secret:

- `TELEGRAM_BOT_TOKEN`
- `LLM_API_KEY`

### 5. Права на запись

Settings → Actions → General → **Workflow permissions** → **Read and write
permissions** → Save. Без этого бот не сможет коммитить состояние и будет
забывать слова при каждом перезапуске.

### 6. Запуск

Actions → **repiter listen** → **Run workflow**. Дальше расписание держит
бота живым само. В логе шага «Слушаем Telegram» должно появиться
`[listen] старт, работаю 5.7 ч`.

Пиши боту `/start`, выбирай язык — и можно кидать слова.

## Оговорки

**Перезапуск смены.** Раз в 5 ч 40 мин бот уходит и его место занимает
следующий запуск. Пауза обычно секунды. Сообщения, отправленные в паузу,
обработаются сразу после старта.

**Правки кода.** Пуш в `main` и ручной запуск заменяют работающего бота
немедленно (`cancel-in-progress`), запуск по расписанию — вежливо ждёт
в очереди. Так правки доезжают сразу, а бот не перезапускается каждые
20 минут без нужды.

**Сон расписания.** GitHub отключает cron в репозитории, где 60 дней не было
активности. Бот пишет в состояние поле `heartbeat` с текущей датой — минимум
один коммит в сутки есть всегда.

**Состояние и конфликты.** Единственный писатель `data/state.json` — бот,
поэтому при сохранении он перематывается на актуальный `origin` и кладёт свой
файл сверху. Твои коммиты с правками кода при этом не затираются.

**Если примеры не генерируются.** В самом начале лога шага «Слушаем Telegram»
бот печатает строку `[проверка] генерация примеров: ...` — там либо
`работает, модель ...`, либо причина отказа прямым текстом. Что бывает:

| Ответ сервиса | Что делать |
|---|---|
| ключ не виден воркфлоу | секрет назван не `LLM_API_KEY` или лежит в Environments, а не в Repository secrets |
| HTTP 400 «Please pass a valid API key» | ключ `AQ.` ушёл на OpenAI-совместимый путь. Убери переопределение `LLM_API_URL` — нативный адрес бот подставит сам |
| HTTP 401 | ключ обрезан при копировании |
| HTTP 403 | ключ ограничен по адресам, либо в проекте не включён Generative Language API |
| HTTP 404 | имя модели неактуально: задай переменную `LLM_MODEL` |
| HTTP 429 | упёрлись в суточный лимит бесплатного тарифа |

На 404 бот сам перебирает известные имена моделей и запоминает ту, что
ответила, — переменную стоит задавать, только если не подошла ни одна.

### Сменить провайдера

Код ни к кому не привязан, нужен лишь OpenAI-совместимый эндпоинт.
Settings → Secrets and variables → Actions → **Variables**:

| Переменная | Пример |
|---|---|
| `LLM_API_URL` | `https://api.groq.com/openai/v1/chat/completions` |
| `LLM_MODEL` | `openai/gpt-oss-120b` |

Плюс новый ключ в секрет `LLM_API_KEY`. Перебор запасных имён моделей при
смене эндпоинта отключается сам.

## Команды

| Команда | Что делает |
|---------|-----------|
| просто текст | добавить слово (несколько — с новой строки или через запятую) |
| `/list` | что сейчас в работе и на каком шаге лесенки |
| `/stats` | сколько закрыто, сколько в работе |
| `/lang` | сменить язык (английский / французский) |
| `/window 10 22` | часы, в которые можно писать |
| `/limit 8` | максимум напоминаний в день |
| `/delete слово` | убрать слово |
| `/pause`, `/resume` | тишина и обратно |

Есть и служебная `/try слово` — собирает напоминание прямо сейчас, минуя
лесенку и не заводя карточку. Нужна, чтобы проверить связь с генератором
и посмотреть на живой результат, не дожидаясь тика. Доступна только владельцу
(`ADMIN_CHAT_ID` в `bot/main.py`, переопределяется переменной окружения
`REPITER_ADMIN_CHAT`), в меню бота не значится, остальным на неё отвечает
обычное «не знаю такой команды». Единственное место, где текст ошибки виден
прямо в чате: команда для того и нужна.

## Структура

```
bot/
  listen.py   живой цикл: long polling + тик раз в полчаса
  main.py     обработка апдейтов и отправка напоминаний
  srs.py      тики и лесенка интервалов
  llm.py      генерация примеров (Gemini Flash-Lite нативно, прочие — форматом OpenAI)
  render.py   тексты сообщений, выделение слова, спойлеры
  store.py    состояние в JSON
  gitsync.py  коммит состояния обратно в репозиторий
  tg.py       клиент Telegram Bot API (только стандартная библиотека)
tests/
  test_flow.py  118 проверок всего сценария на заглушках
data/
  state.json  состояние (коммитится ботом)
```

Зависимостей нет — всё на стандартной библиотеке Python 3.12.

## Локальный прогон

```bash
python -m tests.test_flow          # 118 проверок на заглушках, сеть не нужна
TELEGRAM_BOT_TOKEN=... LLM_API_KEY=... python -m bot.listen   # живой бот
TELEGRAM_BOT_TOKEN=... LLM_API_KEY=... python -m bot.main     # один разовый проход
```

Локально `REPITER_GIT_SYNC` не выставлен, так что бот пишет состояние
только в файл и ничего никуда не пушит.
